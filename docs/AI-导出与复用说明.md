## 二、如何导入其他项目

1. 将 ZIP 解压到独立位置，先读本说明和 [初始化清单](AI-项目初始化清单.md)，检查目标仓库已有规则、文档和工作区。
2. 已有项目逐项合并 `AGENTS.md`、`FILE_INDEX.md`、`SECURITY.md` 与对应主题，禁止覆盖或删减原规则、代码索引和产品 README。只有原本不存在且不会冲突的规范文件才直接复制。
3. 把本包 README 作为包说明保留或不复制，不用它替换产品 README；只在产品贡献指南允许的位置链接实际规范入口。
4. 新项目可以在已批准范围内采用根工作约定和规范，填写 [项目配置](../项目配置.md)，补充真实需求、入口、路径与检查；禁止拿占位配置当作既有能力。
5. 技术栈匹配且采用已获授权时，才在项目配置明确启用对应专项并合并冲突；不同框架只使用通用规则或另行批准的专项。
6. 按实际设计和设备确定 UI；采用桌面控制台配色、10/20/50 页长、1440px、固定错误文案或消息样式必须核对相应范围和政策，不能因为文件存在自动改版。
7. 核实命令、验证和可选技能，执行低风险试运行。报告已合并内容、冲突选择及未验证项；禁止凭模板已复制宣称 CI、权限或生产能力已具备。

这些是一次接入步骤，不要求每项普通开发重新审批。用户已有授权且不存在新实质决策时继续实施。

## 四、未附带与未验证的能力

包内没有应用代码、测试、依赖环境、秘密、运行数据、构建产物、安装/部署脚本、CI、分支保护、外部技能或客户端权限设置。文件存在不表示目标项目有指定框架、组件、认证、数据库或检查命令。

导出只核验规范结构、引用、适配及归档完整性，不对未知目标项目运行应用测试或提供上线结论；下一项目的实现、工具和客户端加载仍按其配置验证。新依赖、外部系统操作、生产发布等不因复制规范自动获准。
