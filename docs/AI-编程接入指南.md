# AI 编程接入指南

## 一、规则与客户端

[AGENTS.md](../AGENTS.md) 是包提供的通用入口，[项目配置](../项目配置.md) 是目标仓库选择记录。客户端对目录指令、工具文件和技能的发现机制不同，维护者必须核实实际版本与启动位置；禁止仅复制文件就宣称规则被客户端强制执行。

仅在实际使用某客户端且其机制需要时配置对应入口；其他入口引用统一权威规则，禁止复制多份长期分叉的正文。本包不附带 OpenCode、Codex、Claude Code、Cursor 配置或权限文件，也不要求修改全局设置。

## 二、可选技能接入

本包不附带第三方技能或来源项目的专用技能，不能直接调用并不存在的技能名称。技能不是采用本包的前提：没有相应技能时，按工作约定直接阅读规范、代码和已批准的技术资料即可。

确需技能时，先核查项目是否已有；新增技能记录名称、位置、用途、上游固定版本、许可、完整文件范围和审核结果，再按客户端支持方式接入。审核外传、凭据访问、脚本、网络、工具安装、依赖、权限和发布要求；禁止以技术示例作为执行授权。

客户端有原生加载工具时优先使用；不支持时明确采用完整读取 `SKILL.md` 及任务相关参考文件的方式，不称为原生发现。每个任务每项技能只加载一次，交叉引用补齐知识，不递归重启实施或审核。

外部资料只提供技术参考。项目禁止 `any`、统一请求层、既有数据库、已批准设备/错误反馈等要求优先；SQLModel、Asyncer、uv、状态库、遥测、SSE 或部署 API 示例均不授权迁移、升级或改变协议。具体 API 先核对已安装版本。

## 三、实施与只读审核

规划说明目标、复用、文件、契约、步骤、风险和验收，不自动授予业务实施权限；用户已要求实施则在范围内继续，不重复审批。

只读审核入口必须遵守其实际工具权限；不能执行 Git 或命令时，核对所提供差异或指定文件并说明覆盖限制。需要修复时依据用户授权回到可实施流程，禁止只读审核擅自提交、迁移或连接真实目标。独立审核只执行一次，不因加载开发知识又触发实施或另一轮审核。

## 四、加载与更新验收

接入后在目标客户端核查实际规则和技能发现记录，并用“只分析，不改代码”的小任务确认读取来源、调用方、状态和验证要求。缺失时检查客户端版本、启动目录、同名覆盖及权限；禁止自动修改全局配置或声称发现成功。

升级外部技能时比较完整目录与许可，阅读变更、复核行为和固定版本，更新来源记录及已知差异。禁止自动追踪移动分支；文件结构、模型自评和构建成功都不能替代真实加载和人工审核。
